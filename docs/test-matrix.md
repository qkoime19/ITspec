# Тестова матрица

Тема 8 — IT помощ: компютри и телефони · Александър Калоянов

Във всяка клетка: `очакван / реален`. Очакваните кодове са попълнени; реалните се попълват след теста в Swagger (или `ITspec.Api.http`). След всеки успешен отговор — проверка в базата със `SELECT`.

| Действие | Client | Technician | Admin | без JWT |
| --- | --- | --- | --- | --- |
| Публикуване на заявка (POST /requests) | 201 / | 403 / | 403 / | 401 / |
| Даване на оферта (заявка Open, своя вид) | 403 / | 201 / | 403 / | 401 / |
| Даване на оферта (заявка Assigned) | 403 / | 409 / | 403 / | 401 / |
| Оферта извън своите видове устройства | 403 / | 403 / | 403 / | 401 / |
| Приемане на оферта по своя заявка | 200 / | 403 / | 403 / | 401 / |
| Приемане на оферта по чужда заявка | 409 / | 403 / | 403 / | 401 / |
| Втора приета оферта по същата заявка | 409 / | 403 / | 403 / | 401 / |
| Завършване на работата (приетият техник) | 403 / | 204 / | 403 / | 401 / |
| Прекратяване на заявка (своя, Open) | 204 / | 403 / | 403 / | 401 / |
| Отзив за Completed заявка | 201 / | 403 / | 403 / | 401 / |
| Отзив за заявка, която не е Completed | 409 / | 403 / | 403 / | 401 / |
| Скритите данни преди приемане (GET /requests/{id}) | 200, без телефон и адрес / | 200, clientPhone = null / | 200, без телефон и адрес / | 401 / |
| Собствено правило: приемане на оферта на техник с 3 поети заявки | 409 / | 403 / | 403 / | 401 / |
| Скритите данни за техник, чиято оферта не е приета | — | 200, clientPhone = null / | — | 401 / |
| Регистрация с подадена роля в тялото ("role": "Admin") | 201, ролята е Client / | 201, ролята е Client / | 201, ролята е Client / | 201, ролята е Client / |

**Кодове, които връща API-то:** 200/201/204 — успех; 400 — невалидни данни (DTO валидация, оценка извън 1–5); 401 — няма валиден токен или грешна парола; 403 — грешна роля, чужд ресурс, вид устройство извън своите, блокиран акаунт; 404 — няма такъв ресурс; 409 — нарушено бизнес правило (грешен статус, дублиран запис, грешки 50001–50013 от процедурите).

Регистрацията не изисква токен, затова колоната „без JWT“ също дава 201; с ролята на текущия потребител няма значение — новият акаунт винаги е Client (адресът `register/client`) или Technician (`register/technician`).
